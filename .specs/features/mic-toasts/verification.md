## Not tested

- [Escolher microfone] and [Resolver] were not clicked: the operator chose not to click, and no
  automation was used. Their commands are covered only by C14 (unit test of the page choice and
  source/binding assertions).
- The chimes were not heard: the runs can't confirm sound. C3 proves the code path; the log has no
  line per chime.
- Mic access denied, no input device, and mic busy (`mic_denied`, `no_mic`, `mic_failed`): no
  clean way to reproduce on this machine. Covered by C2 (classification) and by M1 for the shared
  alone-notice path.
- A Windows-muted physical endpoint: not needed, since the default input already delivered
  silence. The Windows mic mute state was never changed (`muted=False` before and after).
- Blank transcription with signal (AC 9): no run produced a heard recording with an empty
  transcription. Covered by C9 and C11.
- The main-window toast with `model_not_found`/`model_not_downloaded`: the main window was not
  inspected during M1. Covered by C6.

## Findings during the manual runs

1. The app clears a `selected_model` that is not on disk at startup, so the real S11 path is
   `Model not found: ` with an empty selection, not `Model not downloaded`. Fixed in PR1:
   `model_not_found` code and `errors.modelNotFound` (AC 6, C6 widened).
2. An unplanned paste: a recording left open by a lost `--toggle-transcription` picked up room
   speech, and closing it pasted a short English sentence into the window that had focus at
   that moment. That was the normal delivery path working, but text landed where nobody asked for it.
3. Pre-existing, not touched here: `managers/transcription.rs` logs `Transcription result: <text>`
   at `INFO`, which AGENTS.md forbids for dictated content above `debug`.
